# Security Policy

## Supported Versions

Security fixes are applied to the latest version on the default branch. Older
commits, forks, and third-party deployments are not supported.

## Reporting a Vulnerability

Please do not open a public issue for a suspected vulnerability. Instead, email
[benthecarman@live.com](mailto:benthecarman@live.com) with the subject
`OP-RETURN-Bot security report`.

Include as much of the following information as possible:

- A description of the vulnerability and its potential impact
- The affected component, commit, or configuration
- Reproduction steps or a minimal proof of concept
- Any suggested mitigation or fix

Reports involving exposed credentials, wallet keys, payment or invoice
manipulation, authentication bypasses, injection vulnerabilities, or disclosure
of private user data are especially important. Do not include real secrets,
private keys, or other sensitive user data in a report; use redacted or test
values instead.

You should receive an acknowledgement within 72 hours. After confirming the
issue, the maintainer will coordinate a fix and disclosure timeline with you.
Please allow a reasonable amount of time for a patch to be released before
disclosing the vulnerability publicly.

## Safe Harbor

Good-faith security research that avoids privacy violations, data destruction,
service disruption, and access beyond what is necessary to demonstrate the
issue will not be pursued by the project. Follow applicable laws and test
against your own deployment or accounts whenever possible.
